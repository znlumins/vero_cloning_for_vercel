  ---
  Prioritas 1 — Efisiensi Koleksi Data (Paling Kritis)

  Batch Recording Mode
  Sekarang harus klik tombol rekam setiap kali. Untuk 1.300 rekaman SIBI, itu
  1.300 kali klik. Harusnya bisa set target → rekam otomatis berulang tanpa klik
  lagi.

  Konfigurasi Frame per Tipe
  TARGET_FRAMES sekarang hardcode 500 untuk semua. SIBI gesture statis cukup 100
  frame (~3 detik). Dengan 100 frame, bisa kumpulkan 5× lebih banyak data dalam
  waktu yang sama.

  Per-label Progress Indicator
  Sidebar sekarang hanya tampilkan jumlah rekaman. Harusnya tampilkan progress A
  (12/50) supaya langsung tahu label mana yang masih kurang data.

  ---
  Prioritas 2 — Kualitas Data

  Warmup Hand Detection
  Countdown tidak harus menunggu tangan terdeteksi. Bisa saja rekam 500 frame
  tapi tangan tidak masuk frame sampai detik ke-5 — data terbuang.

  Quality Score Otomatis
  Setelah rekam, hitung berapa frame yang berhasil deteksi tangan dan simpan di
  metadata:
  { "handDetectionRate": 0.85, "quality": "good" }
  Rekaman dengan deteksi < 40% ditawarkan untuk diulang otomatis.

  ---
  Prioritas 3 — Siap Training

  Export Format untuk Python/Colab
  Endpoint export sekarang hanya export metadata JSON. Belum ada endpoint yang
  menghasilkan format flat siap numpy:
  GET /api/export/training?signType=sibi
  → X.shape = (n_samples, 100, 258)

  Signer Tag
  Tidak ada info siapa yang rekam. Kalau 5 orang rekam label yang sama, tidak
  bisa dibedakan. Field signerTag di metadata penting untuk mendeteksi
  overfitting ke satu orang.

  ---
  Prioritas 4 — UX & Stabilitas

  Pagination di DatasetList — Kalau 1.000+ rekaman, grid bisa lag/crash karena
  semua di-render sekaligus.

  UI State Persistence — Tab yang dipilih, label yang aktif, reset ke awal
  setiap refresh browser. Harusnya pakai localStorage.

  Bulk Delete — Tidak bisa hapus banyak rekaman sekaligus. Kalau mau bersihkan
  data jelek, harus satu per satu.

● Format data tidak berubah sama sekali. Yang berbeda cuma cara pakai datanya
  waktu training.

  ---
  Penjelasan Simpelnya

  Sekarang misalnya label "A" punya 3 rekaman dari 1 orang:
  dataset/sibi/a/
    uuid-1_landmarks.json  ← orang yang sama
    uuid-2_landmarks.json  ← orang yang sama
    uuid-3_landmarks.json  ← orang yang sama

  Kalau 3 orang berbeda rekam masing-masing 1 kali:
  dataset/sibi/a/
    uuid-1_landmarks.json  ← orang A
    uuid-2_landmarks.json  ← orang B
    uuid-3_landmarks.json  ← orang C

  Isinya sama persis — array 500 frame × 258 features. Model tidak peduli siapa
  yang rekam.

  ---
  Yang Diubah Cuma Metadata (Opsional tapi Bagus)

  Saat ini metadata rekaman seperti ini:
  {
    "id": "uuid-1",
    "label": "a",
    "frameCount": 500,
    "createdAt": "2026-06-08T..."
  }

  Kalau tambah signerTag:
  {
    "id": "uuid-1",
    "label": "a",
    "frameCount": 500,
    "signerTag": "s001",
    "createdAt": "2026-06-08T..."
  }

  Gunanya bukan untuk format training — tapi untuk analisis sebelum training:

  # Di Colab, bisa filter atau split data berdasarkan signer
  # Misal: train pakai s001+s002, test pakai s003 (unseen signer)
  # Ini cara terbaik ukur apakah model bisa general ke orang baru
  df[df['signer'] != 's003']  # training set
  df[df['signer'] == 's003']  # test set

  ---
  Intinya

  - Format landmark JSON → tidak berubah, tetap sama
  - Proses di Colab → semua rekaman label "A" dari siapapun tinggal di-stack
  jadi satu array training
  - signerTag → opsional, tapi bagus untuk validasi model yang lebih jujur

  Jadi tidak perlu khawatir soal format — fokus aja kumpulkan data dari banyak
  orang, sisanya tinggal stack waktu training.

  Mau aku tambahkan fitur input signerTag di app sekarang? Simpel — cukup satu
  field nama/kode di UI sebelum mulai rekam.

  ---
  Opsi A — Upgrade VERO ke MediaPipe Holistic

  Masalah Awalnya

  VERO sekarang pakai MediaPipe Hands di Studio (Translate Gesture). MediaPipe
  Hands itu hanya deteksi tangan saja — 21 landmark per tangan, total ~126
  features.

  Tapi collect_data_tangan merekam pakai MediaPipe Holistic — yang menangkap
  tangan + pose tubuh (bahu, lengan, kepala), total 258 features.

  MediaPipe Hands (VERO lama)     MediaPipe Holistic (collect_data)
    └── 21 landmark tangan kiri     ├── 21 landmark tangan kiri
    └── 21 landmark tangan kanan    ├── 21 landmark tangan kanan
                                    └── 33 landmark pose tubuh
    = 126 features                  = 258 features

  ---
  Kenapa Ini Masalah

  Kalau model dilatih dari data 258 features tapi VERO inference pakai 126
  features → model salah prediksi semua, walaupun akurasi training bagus.

  Ibarat melatih orang mengenali wajah tapi pas ujian dikasih foto setengah
  badan — inputnya beda, hasilnya kacau.

  ---
  Solusi Opsi A

  Upgrade VERO Studio dari MediaPipe Hands → MediaPipe Holistic, supaya input
  inference di VERO sama persis dengan data training:

  Training (Colab)          Inference (VERO Studio)
    Holistic results    ==    Holistic results
    → 258 features      ==    → 258 features
    → LSTM predict            → LSTM predict ✓

  ---
  Kenapa Bukan Opsi B

  Opsi B adalah kebalikannya — training hanya pakai 126 features (hands only),
  VERO tidak perlu diubah.

  Tapi kemarin disepakati Opsi B tidak cocok karena:

  - BISINDO banyak gesture yang pakai gerakan bahu, lengan, dan posisi relatif
  dua tangan terhadap tubuh — kalau tidak ada pose landmark, model tidak bisa
  bedakan gesture-gesture itu
  - SIBI memang bisa pakai hands-only, tapi tidak ada ruginya pakai Holistic
  juga
  - Karena pakai keduanya (SIBI + BISINDO), harus pilih satu format yang cover
  keduanya → Opsi A

  ---
  Yang Harus Diubah di VERO

  Cuma satu perubahan di handLogic.ts — ganti MediaPipe Hands ke Holistic, lalu
  extract 258 features dengan urutan yang sama persis dengan training script
  Python:

  Python (Colab):   pose(132) → leftHand(63) → rightHand(63)
  handLogic.ts:     pose(132) → leftHand(63) → rightHand(63)  ← HARUS SAMA

  di TypeScript dan extract_features() di Python yang sudah diselaraskan.
