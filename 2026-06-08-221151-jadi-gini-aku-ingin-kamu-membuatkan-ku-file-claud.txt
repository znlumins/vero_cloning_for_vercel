● Sekarang aku punya gambaran penuh. Ini analisisku yang jujur:

  ---
  Potensi yang Bisa Ditingkatkan

  1. Strategi Kuantitas Data (Paling Kritis)

  Ini adalah masalah terbesar. Model AI sign language butuh minimum 50–100 
  sampel per label untuk bisa generalize. Sekarang kamu punya 31 label SIBI dan
  masing-masing baru 1 rekaman.

  Yang perlu ditambahkan di app:

  Batch Recording Mode — rekam N kali berturut-turut untuk satu label tanpa
  harus klik berkali-kali:
  Label: "aku" → Target: 50 rekaman → Progress: 1/50 → [Auto rekam lagi]

  Per-label progress indicator — sidebar tampilkan label (3/50) supaya kamu tahu
  label mana yang masih kurang data.

  Multi-signer support — model yang dilatih dari satu orang saja sangat
  overfitting. Kalau bisa, minta 3–5 orang berbeda rekam label yang sama.
  Tambahkan field signerTag (misal: s001, s002) di metadata recording.

  ---
  2. Kualitas Data Recording

  Hand Detection Rate — saat ini tidak ada filter kualitas. Bisa terjadi kamu
  rekam 500 frame tapi 400 frame-nya leftHand: null (tangan tidak terdeteksi).
  Data seperti ini jelek untuk training.

  Solusinya: tambah quality score di metadata:
  {
    "id": "...",
    "label": "aku",
    "frameCount": 500,
    "landmarkFrames": 423,        ← berapa frame MediaPipe berhasil deteksi
    "handDetectionRate": 0.846,   ← 84.6% frames ada hand landmark
    "qualityScore": "good"        ← good/fair/poor
  }

  Recording dengan handDetectionRate < 0.5 sebaiknya di-flag atau dibuang
  otomatis.

  Warmup detection sebelum rekam — jangan mulai countdown sampai tangan sudah
  terdeteksi:
  [Siapkan tangan di depan kamera... ✓ Tangan terdeteksi] → mulai countdown

  ---
  3. Strategi Berbeda untuk SIBI vs BISINDO

  Ini penting banget dan saat ini belum dibedakan:

  ┌───────────────┬─────────────────────────┬────────────────────────────┐
  │               │          SIBI           │          BISINDO           │
  ├───────────────┼─────────────────────────┼────────────────────────────┤
  │ Sifat gesture │ Semi-statik (per huruf) │ Dinamis (per kata/frasa)   │
  ├───────────────┼─────────────────────────┼────────────────────────────┤
  │ Jumlah tangan │ Umumnya 1 tangan        │ Bisa 2 tangan              │
  ├───────────────┼─────────────────────────┼────────────────────────────┤
  │ Durasi ideal  │ 30–60 frame (~1-2s)     │ 100–300 frame (~3-10s)     │
  ├───────────────┼─────────────────────────┼────────────────────────────┤
  │ Yang penting  │ Hand landmarks saja     │ Hand + Pose (bahu, lengan) │
  └───────────────┴─────────────────────────┴────────────────────────────┘

  Rekomendasinya: buat TARGET_FRAMES yang bisa dikonfigurasi per signType. SIBI
  bisa 60 frame, BISINDO 200–300 frame. Lebih pendek = lebih banyak sampel bisa
  dikumpulkan dalam waktu yang sama.

  ---
  4. Export Format untuk Python Training

  Format saat ini (nested JSON per frame) bagus untuk storage tapi tidak
  langsung bisa dipakai Python. Tambahkan endpoint export khusus training:

  GET /api/export/training?signType=sibi&format=numpy

  Yang menghasilkan data flat seperti ini:
  {
    "label": "aku",
    "shape": [500, 258],
    "features": [0.57, 0.23, ...]   ← flattened: pose(132) + leftHand(63) +
  rightHand(63)
  }

  Shape (500, 258) langsung bisa di-load ke numpy:
  import numpy as np
  X = np.array(data['features']).reshape(500, 258)

  ---
  5. Integrasi ke VERO — Ini Ada Gap yang Harus Diselesaikan

  Gap paling kritis: VERO saat ini pakai MediaPipe Hands (handLogic.ts),
  sedangkan project ini collect pakai MediaPipe Holistic. Kalau model dilatih
  dari data Holistic tapi runtime VERO pakai Hands, input feature-nya akan tidak
  match.

  Ada dua pilihan:

  Opsi A — Upgrade VERO ke MediaPipe Holistic (direkomendasikan untuk BISINDO)
  - VERO Studio → Translate Gesture ganti dari MediaPipe Hands ke Holistic
  - Input model: pose + hands (258 features) — konsisten dengan data training
  - Lebih akurat untuk BISINDO karena tangkap konteks bahu & lengan

  Opsi B — Training data hanya pakai hand features saja (lebih cepat 
  diimplementasi)
  - Saat export, hanya ambil leftHand + rightHand dari landmark JSON (126
  features)
  - VERO tetap pakai MediaPipe Hands, tidak perlu diubah
  - Cocok untuk SIBI (alphabet, satu tangan)

  Untuk SIBI → pakai Opsi B, model bisa langsung masuk ke VERO tanpa ubah
  apapun.
  Untuk BISINDO → pakai Opsi A, karena gesture BISINDO butuh konteks pose tubuh.

  ---
  6. Pipeline Integrasi ke VERO (End-to-End)

  collect_data_tangan
    ↓ GET /api/export/training

  Python training script (buat terpisah)
    ↓ Load landmark JSON
    ↓ Normalize + augment (mirror, time-warp, noise)
    ↓ Pad/trim ke fixed length (500 frame)
    ↓ Train LSTM atau Transformer
    ↓ Convert: model.save_format='tf' → tfjs_converter → model.json + .bin

  VERO /app/utils/
    ↓ Hapus modelbisindo.js / modelsibi.js (compiled, tidak maintainable)
    ↓ Ganti dengan tf.loadLayersModel('model.json')
    ↓ handLogic.ts: update feature extraction sesuai format training

  ---
  Yang Paling Prioritas Dikerjakan Sekarang

  Kalau boleh kasih rekomendasi urutan:

  1. Kumpulkan data dulu — 50+ sampel per label dari 3+ orang berbeda. Ini lebih
  penting dari fitur teknis apapun.
  2. Tambahkan quality score + handDetectionRate di server — supaya tau rekaman
  mana yang layak training.
  3. Buat batch recording mode — supaya proses koleksi data tidak makan waktu.
